# Learnings

What went wrong in past QA runs and the rule that prevents it. Read this before a run. Add to it
after a major failure, as [docs/qa-pr-instructions.md](docs/qa-pr-instructions.md#learnings)
describes.

## Android

- android predictive back partial swipe (2026-11-18, [QA of speak-android#9548](https://github.com/usespeakeasy/speak-android/pull/9548)): about 20 minutes lost to reruns. Cause: an `input motionevent` DOWN, MOVE out, MOVE back to the edge, UP chain with no pauses was committed by SystemUI on 3 of 3 tries on develop and on the branch rerun (`CoreBackPreview: onBackNavigationDone backType=4, triggerBack=true`), so the overlay closed after a "cancelled" swipe on both builds. Rule: hold 0.5 s at the far point and 0.8 s plus 0.3 s near the edge before UP (`partial_swipe` in that run: DOWN 3, MOVE 40/120/250, sleep 0.5, MOVE 150/60/10, sleep 0.8, MOVE 8, sleep 0.3, UP 8; 10 of 10 `triggerBack=false` per build), and check `triggerBack=false` in logcat before calling a cancel result.
- android process death on six Navigation 3 entries (2026-11-18, [QA of speak-android#9513](https://github.com/usespeakeasy/speak-android/pull/9513)): about 40 minutes lost. Causes: (1) both API 36 emulators dropped (`adb: device not found`) three times during kill steps with two emulators up, so the rest ran on one emulator; (2) mid AI lesson, `am kill` never kills the app, so `su 0 kill -9 <pid>` is needed, and the resume sheet shows a few seconds after `ai_lesson_screen`, so a check right after the screen saw a reset transcript on one build (`restored-lesson.yaml` now waits 10 s for the sheet); (3) `play-to-card.yaml` leaves can't speak now ON for the install and the cards then move on by themselves, so use `forward-pause.yaml` to hold a card; (4) dev has no active challenge, so Challenge Details and Prizes need a QA-only active challenge in `ChallengeRepositoryImpl.fetchChallenges`; (5) a cold start can show `app_assessment_popup` over Home (now closed in `common/launch-home.yaml`). Rule: one emulator for long process death runs, `kill -9` fallback with a pid check, and start each recording after Home so a case stays under 180 s.
- android narrow width, fold and split screen (2026-11-17, [QA of speak-android#9516](https://github.com/usespeakeasy/speak-android/pull/9516)): about 30 minutes lost. Causes: `wm size 150x2400` is clamped to 200 px, so a width under 64 dp also needs `wm density 640`; at that 12:1 shape Pixel Launcher crashes and its dialog covers the app; `adb emu fold` on the 7.6in Foldable AVD changes the device state but not the display size (use `wm size 904x2316` for the cover screen); in split screen a divider drag below about 600 px on a 2208 px landscape screen dismisses split, and the narrowest split is 741 px. Rule: plan narrow-width cases with these limits, use `wm density` for widths under 76 dp, and close the launcher dialog before the recovery check.
- android prod (`com.selabs.speak`) runs with these flows (2026-11-15, 4.75 release sweep, thread C0C8G9VS2KX p1794718120582999): the first productionRelease Before pass ran the dev app and was thrown away, about 15 minutes lost. Cause: a flow's `env: APP_ID: com.selabs.speak.dev` default wins over `maestro test -e APP_ID=com.selabs.speak` for subflows run with `runFlow`. Rule: for a prod run, check the first flow's `Launch app "com.selabs.speak"` line before the case script, and change the defaults locally to `${APP_ID || "com.selabs.speak.dev"}` for the run (don't push the bulk edit). Free prod accounts: Profile's `stat_streak_title` sits below the Premium card, so assert `stat_sentences_title`; 4.74.0 Free Talk has no `ai_tutor_community_tab_*` IDs, so the Top filter on 4.74 needs the `Top` text. The Free Talk Community `free_premium_button` card loads a few seconds after the tab on both builds; wait for it or revisit Topics then Community before calling it missing.
- android signed-out cases after signed-in ones (2026-11-14, [QA of speak-android#9420](https://github.com/usespeakeasy/speak-android/pull/9420)): case 5 (B2B invite, signed out) and cases 6 and 7 lost about 20 minutes to reruns. Cause: one script ran the cases in sequence, so case 5 started signed in from case 4 and case 7 started on case 6's Home. Fix: start every pre-auth case with `qa_android.py fresh` and set the kill switch override again (pm clear drops it); signed-in cases log in only when `home_root_ready` is missing.
- android onboarding post-sign-in language steps (2026-11-14, [QA of speak-android#9401](https://github.com/usespeakeasy/speak-android/pull/9401)): about 35 minutes lost to two known causes. The case script relaunched after `am kill` with `monkey` (LeakCanary opened on 3 of 6 passes), and a rotation case used `user_rotation 1` on the portrait-only `SpeakActivity`, so it recreated nothing. Rule: grep this file for "process death" and "rotation" before writing those steps. For a recreate check on `SpeakActivity`, use `adb shell settings put system font_scale 1.3` and then `1.0`. It is not in `configChanges`, so each change recreates the activity: controllers log `instance state saved` and `view state restored`, and entries log `instance state saved`. Reset it to 1.0 before the next case.
- android lesson end review prompt on a tutor lesson (2026-11-14, [QA of speak-android#9415](https://github.com/usespeakeasy/speak-android/pull/9415)): about 30 minutes and two rebuilds lost. The QA-only `Screen.AskForReview` patch in `LessonEndFlowViewModel.updateScreens` (both after the first step and right after `LessonCompleted`) never showed the dialog after `EN_ES_A1-1_quetal_SP_DL_IC` (a tutor lesson: LessonEndCompleted then LessonEndReskin then Home), so `lesson-to-home-with-review.yaml` failed on develop. Rule: for review prompt cases open `speak-dev://debug-lesson-end?screens=ASK_FOR_REVIEW,SUMMARY` with `debug-lesson-end-open.yaml` (demo data, no patch, no rebuild), then the `ask-for-review-*` flows; use `lesson-to-home.yaml` for a plain lesson end to Home.
- android ai-lesson final turn (2026-11-10, [QA of speak-android#9194](https://github.com/usespeakeasy/speak-android/pull/9194)): `finish-lesson.yaml` failed on develop on both kill switch passes, about 15 minutes lost. Cause: `type-turn.yaml` waited for `^Reply\.\.\.$` after the partner had already ended the lesson, and Lesson Completed replaced the reply field. Rule: the reply wait after a turn is optional (applied in `android/flows/ai-lesson/type-turn.yaml`).
- android emulator dropped mid-pass (2026-11-10, [QA of speak-android#9194](https://github.com/usespeakeasy/speak-android/pull/9194)): `emulator-5554` went `not found` during cases 7 and 8 of a pass with two API 36 emulators running long AI lesson cases; the recordings broke. Rule: after an `adb ... not found`, restart that emulator, re-apply Developer options (Don't keep activities) and debug props, and rerun only the broken cases on that build.
- android expression-details sheet drags and long cases (2026-11-10, [QA of speak-android#9191](https://github.com/usespeakeasy/speak-android/pull/9191)): about 40 minutes lost. Causes: a drag that started at 40% of the screen began on the scrim of the Navigation 3 sheet (half height, 50%) and closed it, while the controller sheet (peek, about 70%) took the same drag; the immersive AI lesson setup takes 4 to 7 minutes in Maestro, so a recording started before it hit the 180 s `screenrecord` limit before the case's arrival; and editing a case script while bash still ran it broke the run. Rules: start sheet drags below the middle of the screen, and expect a half height Navigation 3 sheet to close on a drag down (`expression-details/drag-at-top.yaml` and `back-to-origin.yaml` already allow it); start the recording after slow setup flows (`ask-ai-lesson-tutor.yaml` is split from the tap for that); copy the case script before editing it mid-run.
- android singles carousel card tap (2026-11-10, [QA of speak-android#9178](https://github.com/usespeakeasy/speak-android/pull/9178)): case 8 lost about 15 minutes. Cause: `tapOn` with `childOf: id: singles_carousel_item` resolves the parent to the first matching carousel item only, so any card after the first was "Element not found" although `maestro hierarchy` showed it. Rule: pick a repeated item by its own text and id, without `childOf` on the repeated parent (applied in `android/flows/singles/details-open-card.yaml`).
- android phone-speak (2026-11-09, [QA of speak-android#9133](https://github.com/usespeakeasy/speak-android/pull/9133)): two base passes lost about 15 minutes. Causes: the call timer reads `01:05` (two-digit minutes), so a `^1:..` wait never matched and calls ran past the 180 s `screenrecord` limit; and the survey sheet is its own window, so a `dump` taken once it shows sees only the sheet, not "Preparing feedback..." under it. Rule: wait for `text:^01:(0[2-9]|[1-5][0-9])$` to hold a call over 60 s, start `rec` after the opener flow, and `dump` once right after End call, before the survey arrives.
- The automotive (AAOS emulator) cases for Free Talk immersive lost about 40 minutes to setup ([QA of speak-android#8992](https://github.com/usespeakeasy/speak-android/pull/8992), 2026-11-09). Causes: `qa_android.py login` starts `com.selabs.speak.SpeakActivity`, which is not exported on `automotiveDevelopDebug` (`SecurityException`); `speak-dev://debug-menu` resolves to no activity there; `qa_android.py shot` writes a "Multiple displays" warning ahead of the PNG because AAOS has a cluster display; the app runs as user 10, so `pm grant` without `--user 10` leaves the mic prompt over the lesson; and the pre-lesson start button sits below the fold in landscape. Rule: sign in with `qa_android.py bridge login`, open the app and Debug Menu with `-e AUTOMOTIVE=true` (`common/launch-home-automotive.yaml`, `common/open-debug-menu-automotive.yaml`), strip the bytes before `\x89PNG` in AAOS shots, grant with `pm grant --user 10`, and let the flow `scrollUntilVisible` to `ai_lesson_pre_lesson_start`. `adb screenrecord` on AAOS emits no frames while the screen is still, so a static case mp4 can be only a few seconds long.
- Phone speak ring microphone case lost about 20 minutes ([QA of speak-android#8712](https://github.com/usespeakeasy/speak-android/pull/8712), 2026-11-09). Causes: a failed earlier case left Ring my phone on (the server keeps it), so the next case's tap turned the ring off and no microphone prompt could show; and once the app has asked for the microphone, reinstalling with `install -r` keeps its asked-before state, so a later ring on shows only the notice. Rule: each ring flow ends with the ring off, so after any failed ring case reset with `pm clear` and a fresh login, check the ring is off before the next case, and revoke the mic with `pm revoke` plus `pm clear-permission-flags <pkg> android.permission.RECORD_AUDIO user-set user-fixed`.
- android storybook process death (2026-11-08, [QA of speak-android#9107](https://github.com/usespeakeasy/speak-android/pull/9107)): Developer options > Background process limit > No background processes did not kill the dev app on the API 34 AVD; `pidof` showed the same pid 15 s after Home on all four runs, so the first pass proved nothing about process death. Rule: set the limit with `system-settings/set-background-process-limit.yaml` when asked, but still record `pidof` before and after Home, and fall back to `am kill` once a second until `pidof` is empty. Log which one killed it.
- Don't keep activities cases on the API 34 AVD lost about 15 minutes ([speak-android#9084](https://github.com/usespeakeasy/speak-android/pull/9084), 2026-11-08). Cause: `adb shell settings put global always_finish_activities 1` only writes the setting; the activity manager keeps activities alive, so Home and relaunch showed no `view destroyed` / `instance state restored` lines and the case proved nothing. `settings put global development_settings_enabled 1` alone also leaves the Developer options intent on `DevelopmentSettingsDisabledActivity`. Rule: turn on Developer options with `android/flows/system-settings/enable-developer-options.yaml`, flip the switch with `toggle-dont-keep-activities.yaml`, check `settings get global always_finish_activities`, and confirm `MainController view destroyed` in the lifecycle log before trusting the case. Flip it outside the case recording; the Settings scroll takes about 90 s.
- The Android 4.74.0 global regression lost about 40 minutes to two causes. A flow env default with a `$` in it (`LOOP_TEXT: ${LOOP_TEXT || "^Introduction$"}`) was not evaluated, so `tapOn` looked for the literal `${LOOP_TEXT || ...}` text and the 4.73.0 lesson cases failed three times; and an `adb logcat` started by an earlier run was never stopped, so the base build's lifecycle file kept collecting the branch run's lines and a per-case diff compared the branch with itself (0 lines of diff). Rule: no `$` or regex anchors in env defaults (Maestro text matching is already a full match); before a run's logcat starts, check `pgrep -af "adb logcat"` and stop any left over. - AI lesson chat-mode cases for the tutor and keyboard buttons lost about 15 minutes. Causes: the pre-lesson Chat/Immersive toggle (`ai_lesson_immersive_toggle` on) keeps the last mode, so after one immersive run `open-free-talk-scenario.yaml` opened immersive (its `Chat mode` text tap no longer matched); in keyboard input the IME and field cover the bottom controls, so a typed turn never shows the Loading state; and switching back to voice, or Back from the tutor sheet, starts recording, which hides the keyboard button behind `ai_lesson_record_cancel`. Rule: the flow now taps `mode_toggle_chat`; see the Loading state in voice mode (Record, then Send with no speech hides the tutor for about 1.5 s; read it from the recording's frames); tap `ai_lesson_record_cancel` before checking idle voice controls. ([QA of speak-android#8954](https://github.com/usespeakeasy/speak-android/pull/8954), 2026-11-06)
- About cases on the China launch market took about 40 minutes to set up. Causes: on the global `developDebug` APK a China launch signs in with a Speak session, not Firebase, so `qa_android.py login` fails with `Default FirebaseApp is not initialized`, and the China and Global launches keep separate sessions (China shows the static dev phone account, Global the pool account); and a case read an About sheet left open from the previous case instead of a fresh one. - Video lesson video-controls, buffering and case 1 completion checks failed for about 60 minutes on both builds. Causes: after a segment's last card the "Tap any word" tooltip pauses playback (`pausePlaybackForTooltip`) until a word is tapped, so the video never resumed; the player controls auto-hide about 2 s after a tap, faster than a Maestro `tapOn` plus `assertVisible` or a harness `tap` (which waits for a fresh tree); and `dump`/`has`/`wait` hang or return nothing while the video plays because the tree never goes idle. Rule: write `seen_word_meaning_tooltip=true` and `pronunciation_coach_word_tapped=true` into the per-user pronunciation prefs before completion and controls cases (keep them false only for the tooltip case); show and pause the controls with one adb shell call (`input tap` on the player, `sleep 0.5`, `input tap` on `play_line`), then read `video_progress_elapsed`/`video_progress_remaining` from the paused tree; check buffering with a pixel read of the `buffering_dots` area on the screenshot, because the node stays in the tree when hidden. ([QA of speak-android#8904](https://github.com/usespeakeasy/speak-android/pull/8904), 2026-11-05)
- Video lesson cases that needed a saved card (resume prompt) or a restored dialog failed for about 40 minutes on both builds. Causes: `play-to-card.yaml` waited for a fixed card (`1 of 4`) that the lesson's next segment did not have, so it stalled on `2 of 2`; after a dialog closed the player could sit paused with no `paused_header`; and `restored-card.yaml` expects `card_count`, but after process death Conductor restores the open More options list or quit sheet over the lesson. Rule: wait for the card number to change instead of a fixed card when you only need progress, `play-to-card.yaml` now turns on can't speak now and taps `play_line` when stuck, and use `restored-more-options.yaml` or `restored-quit-sheet.yaml` after killing the app with a dialog open.
